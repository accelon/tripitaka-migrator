# 位置轉換模塊

## 前置作業 
利用K.db, T.db 以及編寫好的經卷讀取及經卷對照功能。

## 任務
1. 生成一個 網頁和bun cli 都可以用的 typescript模塊，輸入大正藏的位置（經卷、冊頁碼），給出精確到字的高麗藏位置（用頁碼之後加兩位數字，因為每行的文字絕不會超過99） ，  依賴 sqlaccess.ts, T.db , K.db ，也可以設計新的 db ，省去diff的算力。
2. 如果輸入的大正藏位置是高麗藏缺少的序文或附文，那就返回最接近的高麗藏位置（跳過序文），以及對應的大正藏精確位置。
3. 每行大正藏經文、高麗藏經文都是相當固定的字數（不計入標點、標記，只算CJK 表意字符，注意 surrogate pairs，如有IVS異體字代碼可去除之）。設計一個精簡表達 vol + page + col + line + rune offset 的結構，有機會塞入一個 typescript 的 Number 。
4. 參考source map，設計一個記錄文本位置差異的精簡結構，將 diff 的結果保存起來，客戶只需要位置的轉換，不需要看到文本。只需記錄經文位置的差異點，就可以實現大正藏位置到高麗藏位置的換算。這
5. 表示位置的行業慣例是這樣的：T01p0002c0405 意思是大正藏第一冊第二頁第三欄第四行第五個字符偏置，字符偏置若為0時，可省略 。T 改為 K 表示高麗藏。
6. 關於 rune offset （字符偏置），以「如是我聞」為例，0表示「如」字的的左邊，1表示「如」字的右邊，也是「是」字的左邊。就是字符串的指針。
7. 先以「長阿含經第一卷」（大正 0001 經，高麗 0647 經）為試驗對象。驗證以上思路。
8. 本任務可以概括為：輸入 T01p0002c0405 快速計算出（不再依賴 K.db, T.db ) 精確對應的 高麗藏位置 K 以及修正後的 T 位置（輸入指向序文的話，跳過它到該卷正文第一字。輸入若指向附文，則回到該卷正文最後一字的右邊偏置）

convert_taisho_goryeo(taisho_address), 返回 korean_address, adjusted_taisho_address

9. 成功的話，再聽我的指令進行全數據庫的計算。
